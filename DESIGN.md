# Product and interface design

## Purpose

Eratic helps someone turn a music collection into a curated, portable deck of timeline quiz cards. The editor emphasizes which recording is intended, why its answer year is correct, and what a QR will actually open. It is an independent project; the interface does not use Hitster branding or imply endorsement.

The product has two surfaces: **Deck**, which prepares decks, and **Play**, which hosts the nine [game modes](docs/game-modes.md) with a camera scanner and Spotify or Apple Music playback. A live playlist importer and a print designer are future surfaces, not hidden or disabled features.

The native Deck/Play selection is explicit state: starting or resuming a game keeps Play selected as its setup screen becomes the host screen.

## Platforms

Universal means **Mac, iPad, and iPhone**, using a shared native SwiftUI source tree. The web companion is independently usable in a browser. Both exchange the [same deck format](contract/README.md); visual components follow their platform rather than sharing rendered UI.

Mac and larger Apple screens use a native sidebar/detail workspace. iPhone uses the adaptive navigation behavior of `NavigationSplitView`. The web uses a list and inspector side by side above 720 CSS pixels and stacks them below that breakpoint. Maintain reading order and usable controls when the screen narrows.

## Deck interaction model

1. Open the fictional sample or import a JSON deck. Invalid imports show an error and preserve the current deck. On the web, an import that would replace a deck already stored on the device, or changes that browser storage refused, asks first ("Replace the deck stored on this device with “Title”? Export the current deck first to keep a copy."). If the web app finds a saved deck it can no longer read (for example after a validation rule changed), it opens the sample, keeps the unreadable data aside, and offers **Download unreadable saved data** or **Discard it** in the notice area; it never overwrites that data silently.
2. Choose a card by stable ID. The list shows its title, artist, and curated answer year as a chip in that year's era colour. Choosing a card is the signature moment: the inspector opens in the card's era and the year drops in.
3. Edit the answer year and its evidence/source, then explicitly save. When browser storage refuses the save, the change stays in memory, the field says *Not stored on this device* instead of *Changes saved*, and the notice asks for an export. A saved year in another decade re-themes the card at once. Apple also exposes the year note; web preserves notes through edits and export. Validation messages come from the shared core rules; Apple additionally asks for a whole-number year before validating.
4. Inspect a QR route. Official mode is the default and requires a supplied mapping. Its presence is always unverified, not a playback success state. Direct provider mode requires explicit selection and identifies its destination.
5. Export JSON to transfer or back up the deck. The Apple app holds edits in memory until export; until then the card list header says "unsaved edits, export to keep them", importing another deck asks *Replace the deck with unsaved edits?*, and quitting the Mac app asks *Quit without exporting your deck edits?*. The web stores imported and explicitly saved decks in browser local storage when available. Neither provides cross-device synchronization.

An official mapping does not prove that the curated song matches its catalogue entry. A valid provider URL does not prove regional availability. Keep these distinctions visible at the relevant action without filling the editor with implementation detail.

## Play interaction model

The rules are in [contract/game-rules.md](contract/game-rules.md); this section is how the apps present them. One **host** device runs the game for a room of players. Everything below applies to both apps; the platforms differ only in their native controls.

**Navigation.** Deck and Play are the two top-level destinations: a two-item navigation in the web header (with `aria-current`), a `TabView` on Apple. Switching never loses an in-progress game; it is saved after every action. The build ("Eratic 0.1.0 (…)") and *Copy diagnostics* sit in the web page footer and at the bottom of Apple's Play home; the copied text holds the build, the browser or system version and the last 50 problems the app showed, kept in memory (and Apple's system log) on the device and never sent anywhere. The clipboard falls back to a downloaded text file on the web.

**Play home**, top to bottom:

1. **Resume** banner when a saved game is unfinished: mode, players, round and the game's deck title ("Bullseye with Ada, round 2 · A small collection"), with *Resume* and *Discard* (which asks first). A reveal or final result the host hasn't seen yet is shown again on resume ("Results waiting"). The web offers finished results (*Show results*, *Dismiss*) until the host leaves them with *New game*; restoring an unseen reveal is Apple-only. Starting any new game, Daily included, asks before it replaces an unfinished one; an unfinished Daily for today offers *Resume today's round* instead. A saved game that can't be read or replayed is kept aside, never deleted silently: the notice offers *Download unreadable saved game* and *Discard unreadable game* on the web, *Export unreadable saved game* and *Discard* on Apple; both Discards ask first; the notice stays until the game is discarded (on Apple an export keeps *Discard* offered, since the Sessions folder is out of reach on iOS). A running or resumed game always plays against the copy of the deck it started with; if the open deck with the same ID has changed since, the host says so.
2. **Playback**: Spotify, Apple Music and Play it yourself are always selectable. *Use playback* reuses existing Eratic authorization when available and otherwise enables QR/song-link playback without a sign-in prompt. Native Apple Music asks for system music permission and reads the device's subscription. Native song links prefer the installed music app, falling back to the website. Browser links use the app/browser's own signed-in account; a website cannot inherit a native app's authorization. *Enable timed clips* is an optional, separately labelled authorization action shown only when the integration is configured (Spotify on native; either provider on web). Failed connections fall back to manual playback. The status says "Spotify: manual playback (Free or Premium)" when subscription status is unknown, rather than claiming a detected Free account. Spotify Free playback remains subject to the provider's limits. With exact clips, a *Calibrate timing* button and the last result (ADR 0011); a failed or missing calibration shows a warning on Snippet Ladder, never a block. See [ADR 0014](docs/adr/0014-app-first-playback.md).
3. **Daily Eratic** card: today's status (an unfinished round says "under way" with *Resume today's round*), *Play today's round* starts at once on both platforms (one player, named "You"; on the web it asks first only when it would replace a saved game), streak (0 once a day is missed), and the share text once played. Daily always draws from the whole deck, ignoring *Easy cards only*, so everyone's day matches; it has no *Skip card*, because a skipped Daily card can't be replaced, so when some of today's cards have no song link at all, a muted line says "2 of today's songs have no song link; you'll guess those without hearing them."
4. **Mode gallery**: nine tiles in the mode overview’s order. Each shows the name, the pitch, the player range, and, when the mode can't start, the reason in words: "Needs linked recordings" (Original or Imposter without pairs), "Deck too small". Every mode can start without exact clips, because every card in play has the song backup (below). Without exact clips, Snippet Ladder plays its steps as snippets of the hidden preview (below); only when the card has no Spotify/Apple Music preview do the step buttons become *Mark 1 s played* / *Next: mark 5 s played* (the host plays the step by hand from the backup). Lineup and Original or Imposter play their tiles as preview snippets too; a tile without a preview, or whose preview fails to load, shows its title (Lineup) or is played by hand from the backup (Imposter, so the titles don't give the pair away). Lineup is offered as *Lineup by name* only when no card in the deck has a preview. A game started without *Use playback* runs as Play it yourself.

**Setup.** Players (or teams) as a list of name fields with *Add* and *Remove* within the mode's range, prefilled with the last game's roster (clamped to the range) or "Player 1"…; names never leave the device. The mode's options with the contract defaults, in plain words. A **Kids** switch where supported (Timeline, Era Sort): Beginning anchor, no challenges, adjacent-era credit, larger controls, no timers. Timeline's Kids only presets the options below when switched on ("You can still change the options below."); they are not overridden at *Start*. Duplicate player names are rejected ("Names must differ."). Options with no effect are hidden: Timeline's *Tokens* and *Name It* need *Challenges* (hidden, they are not sent), Snippet Ladder's *Clip start for cards without their own* needs exact clips, and a custom anchor year starts at the deck's median year. With **Stakes** on, a muted line says "Everyone starts with 5 chips; your score is your points plus the chips you hold."; Timeline words it "on each placement". **Easy cards only** when the deck has difficulty values. **Card source**: *Scan printed cards* (when a camera exists and the mode takes single cards: not Daily, Higher or Lower, Lineup or Original or Imposter) or *Draw from deck* (the default on Mac and web). Until printing exists, choosing *Scan printed cards* explains how to make a scannable code: a card's direct-link QR from the Deck tab, shown on another screen or printed. Starting while an unfinished game is saved asks *Replace the unfinished game?* first. Higher or Lower adds *Who calls each card* (*Take turns* or *Everyone, with lives*, with a lives stepper) and *Closer years as the game goes on*; Snippet Ladder adds *Buzzer: +2 for the first lock-in that scores* ([ADR 0017](docs/adr/0017-everyone-calls-closer-draws-buzzer-and-relation-suggestions.md)). Snippet Ladder's clip steps are toggles on both platforms (1·5·10·20·30 s, kept in increasing order; "Choose at least one step." when none). Preview-only accounts see which Ladder steps were left out. When the deck holds fewer cards than the chosen rounds or target allow, a muted line under the field says so ("This deck has 3 cards: enough for 3 rounds."), and the field starts at what the deck holds (Lineup at three songs when it can't hold four); *Start* is never blocked for it. *Start* creates the session with a random seed; Timeline and Relay anchors are picked with `pickAnchors` and announced: "Give Ada *Paper Satellites* (1984) as their first card."

**Host screen.** On iPhone and iPad the screen stays on while it is open. A top bar with the mode, the round ("Round 3 of 10", "First to 10 cards"), *Play home* (web and Apple; an unfinished game stays saved for *Resume*) and *End game*, which asks first and says what ends: "Players tied for first go to sudden death.", "The tie stands." in a sudden death, else "The standings so far become final."; a card in play "isn't scored". The scoreboard stays at the start of the round while its reveal shows. A scoreboard with every player's score (the large line) and, where used, chips, tokens or lives; on Apple it wraps into a grid instead of scrolling sideways, so every player shows on a phone. The active player is marked in words ("Ada's turn"), not only by colour. On a narrow iPhone the top bar folds *Play home* and *End game* into a *More* menu. Errors show with a warning symbol in dark red and are announced to VoiceOver; the iPhone number pad has a *Done* key, and scrolling dismisses it. The **card stage** in the middle:

- Before a card: *Draw card* or *Scan card*. When the deck can't supply the next card, the stage says "The deck is used up after 3 rounds." ("No pairs left after 3 rounds." for Original or Imposter) with *Show results*, which ends the game without asking; a tie that can't draw its sudden death says "Not enough cards left for sudden death (it needs 1). The tie stands." and *Show results* keeps the tie. A scan that resolves to a card already played warns and is ignored; a card from another deck names that deck; a provider link that isn't in the deck offers *Play audio only (not scored)*.
- With a card in play: a mystery card on the stage colour, *Play* / *Replay* ("Preparing…" while the provider loads the song), and a clip indicator that shows a playing dot and a countdown in text, so players who can't hear well can follow. Without exact clips the button says *Play on Spotify* (or Apple Music, after the link it will actually open) and opens the song in the provider's own app or site; a card without a link for that provider falls back to *Open song link*. A clip stops when the host leaves the host screen. *Skip card* (unavailable song) is a secondary action; it asks first when the card already has entries, because skipping discards them. Clip start: the card's value, else the deck default, else the session choice; the host can nudge it by ±5 s for this card.
- **Song backup** in every mode, for every card in play, whatever the provider or tier: the song's link as a QR code ("Scan with a phone to play the song there"), so a player can start the song on their own phone without the title appearing on the shared screen, and the hidden preview below. The link is the chosen provider's, else the card's first Spotify or Apple Music link, else its first link. Without exact clips the backup is shown openly; with exact clips it sits behind a closed *Backup: song QR and hidden preview* disclosure, and starting an exact clip stops the preview. Lineup and Original or Imposter show one backup at a time, picked with *A*, *B*, … buttons.
- **Inputs** for the mode (below). Guesses are entered one player at a time and shown as "Locked" until the reveal, so the host device can be passed around. Bullseye and Era Sort also offer *All at once* for two or more players (remembered per device): one form with every player's field and *Lock in all*, for groups who write guesses down or call them out; nothing is recorded unless every row is valid; each row is a card of its own, with the name above its controls on a narrow screen. Right after *Lock in all*, *Undo all entries* takes back exactly that batch (only entries and clips; it disappears once anything else happens). While *Reveal* waits, "Still to answer: Ada and Lin" says why. *Undo Ada's entry* (*Undo your entry* for a lone player) takes back the last entry before the reveal (a lock, placement, call, challenge, Name It, wager or order; a Bullseye guess goes with its wager). It never removes a played step or a draw, and it is hidden while the Snippet Ladder answer is open on the web. *Play* says *Preparing…* while the provider loads the song. In sudden death the banner also states the rule ("One song. The closest year wins.", "Order 3 songs. The best order wins.", "One 5-second clip. The first to name the song wins."), on both platforms. Kids enlarges the mode's controls and the host's action buttons (Reveal, Next, Undo, Skip).
- **Embedded preview** (part of the song backup): one *Play preview* loads the provider preview only when requested and starts it in a hidden player. Spotify can ignore the first play request or the browser can refuse audio once the click is old: a silent autoplay is retried once after 2 s, and if it is still silent 4 s later the preview returns to ready with *Play* (a fresh host gesture) instead of staying on "Starting…". The host then has *Play*/*Pause*, *Back 10 s*, *Restart* and a position slider with elapsed/total time, so they can stop, rewind or jump to another part without the song showing. Spotify's player stays concealed from view, focus and accessibility until *Show player (reveals song)*. Apple Music plays the song's public 30-second preview file directly, so it never needs revealing; when Apple lists no preview, the fallback is the revealed player (*Show Apple Music player (reveals song)*, *Hide player* keeps audio, *Stop preview* removes it). Loading, starting and Apple buffering have bounded waits. An error ends the attempt and retains retry/fallback controls; late provider events cannot restart it. Retry creates a fresh attempt, as does showing Spotify's player after an error. Opening Apple's revealed fallback disposes hidden playback first. QR and app links remain available. These previews have provider-controlled length and never count as exact clips; modes without exact clips are played by hand from them. Changing cards, revealing, leaving the stage or opening the external song removes the embed; native backgrounding also unloads it.
- **Reveal**: the signature moment. Keyboard focus moves to the reveal, and screen readers hear a one-line summary (VoiceOver announces it natively). The card's era takes over the stage (ground, pattern on the web, era label), the year drops in, then the title and artist (about 0.35 s later), then each player's result ("+7, 1 year off", about 0.7 s) and a leader line ("Ada takes the lead with 23.", "Ada and Lin share the lead with 20."; not in Relay, Daily, solo games or sudden death). *Next card* (*Next pair* in Original or Imposter, *Next lineup* in Lineup) continues and draws the next card in one step. In Relay with Name It, the line says "Named it: a life back before the placement." or "Named it, but lives were already full.". Reduce Motion shows everything at once.

Sudden death replaces the inputs with a banner ("Sudden death: Ada and Lin") and the kind's inputs: a year each, an order of four cards, or "Who named it first?". Wagers (Stakes) are a 1–3 control per player, disabled with the reason at 0 chips, with a muted line on what wins it (Bullseye: within 3 years; Snippet Ladder: lock in and score; Timeline: a right placement).

During a reveal, the round label names the round just played until the host advances. Native reveal, next-card and results transitions bring the new content to the top of the scroll area; entry edits and undo preserve the current position. Bullseye rulers use inclusive year cells and keep their bands and numbered markers inside the visible width in both apps, including for widely separated guesses; the textual guess/answer list remains authoritative.

**Results.** Standings with shared places shown as "=1" (read as "shared 1" by screen readers), each player's score (points; Timeline counts cards, "7 cards", or "7 (cards + chips)" with Stakes; Higher or Lower says "streak 5"), Relay shows its team result instead of standings, and the mode's tie-break numbers, a closed *Card by card* recap (each revealed card and who scored best on it, by points rather than chips), a personal best for Relay and one-player games ("Best: 12" or "New best: 31!", kept per deck on the device), then *Play again* (same players and options; the deck open in the app when it is the game's deck, else the game's own copy), *New game* and *Export session* (web: *Download session JSON*). Daily adds the share text. Finished results the host hasn't seen are offered again after a relaunch.

**Deck fields for games** (deck version 2). The card inspector gains an optional *Game* section: clip start (seconds), difficulty (1–5) and a related recording (another card plus *original of*, *cover of* or *remaster of*); the deck gets a default clip start. A closed *Suggested linked recordings* section lists cards whose titles match ("Song — cover of Song (1965)"), each with *Link* and *Dismiss*; suggestions are never applied without a tap and should be checked first. Saving the first such value converts the deck to format version 2 and says so once: "Saved as deck format 2; older Eratic versions can't open it."

## Brand: Eratic

**Name and voice.** *Eratic* is *era* plus *tic*. The bold "era" and light "tic" make the split readable before anyone sees a misspelling, and the tagline owns the joke: **Spelled wrong. Dated right.** The secondary line is *Every era has a move.* The tone is a clever party game: playful, never snobbish.

**Wordmark.** In the wordmark, "era" takes the style of the era currently on screen, while "tic" stays light and steady. The dot of the i is a QR finder square. The app icon is a lowercase *e* over nine decade bands. This file and `design/eras.json` define the maintained visual direction. The web favicon is `apps/web/public/favicon.svg`.

**Stage and spotlight.** The app chrome is a calm stage: dark *stage* `#17131C` for the header, warm *paper* `#F7F2E8` for the workspace, and white panels. Era colours appear only on era content: year chips, the inspector hero, the wordmark's "era" and, later, the answer side of printed cards. QR codes are always black on white with a four-module quiet zone, and no era colour or pattern ever touches them.

### The nine eras

[`design/eras.json`](design/eras.json) is the single source of truth, read by `apps/web/src/ui/eras.ts` and bundled into the Apple app (`Sources/Era.swift`). A card's curated year picks its era. This is presentation only and never changes deck data.

| Era | Years | Look | Type move |
| --- | --- | --- | --- |
| Shellac | before 1950 | Sepia paper, deco fan lines | Narrow capitals, wide tracking |
| Jukebox | 1950s | Cream, navy, cherry polka dots | Heavy |
| Mod | 1960s | Off-white, black, orange target roundel | Narrow, heavy, tight |
| Disco | 1970s | Plum ground, amber sunset bands | Full width, bold |
| Neon | 1980s | Midnight, magenta and cyan laser grid | Heavy capitals with glow |
| Zine | 1990s | Photocopy grey, black and blue halftone | Narrow capitals, knocked 2° off straight |
| Chrome | 2000s | Ice blue, brushed-metal lines, aqua pill | Slightly narrow, semibold |
| Pastel | 2010s | Blush, flat circles, raspberry | Light, lowercase |
| Now | 2020s and later | Black, acid-lime dot grid | Heavy, lowercase, tight |

Patterns are made only of stripes, dots and rings, which are CSS gradients on the web (`eras.ts`), kept in step with the token colours by hand. Apple currently carries an era's ground, colours and type move but not its pattern. Control borders are `#8A8072` on white or paper and `#7A7085` on the stage, which keeps them above 3:1.

**Type.** On the web, everything is set in one variable family, Bricolage Grotesque, bundled locally (see [attribution](docs/ATTRIBUTION.md)). Each era moves along its width (75–100%) and weight (300–800) axes. Apple uses the system font with matching width (compressed, condensed, standard) and weight. Don't force web pixel values into native layouts; keep the meaning consistent instead.

**Contrast.** `apps/web/src/ui/eras.test.ts` enforces every era pair; `EraticCore`'s `EraTokensTests` checks the token format and era boundaries on Apple:

- text on an era ground: at least 7:1;
- the accent year on its ground: at least 3:1 (display size);
- text on an accent fill: at least 4.5:1;
- an era's glow on the stage: at least 4.5:1.

**Motion.** The year and the wordmark's "era" drop in with a short overshoot whenever they change. When a saved year moves a card into another era, the inspector's ground and text cross-fade over 0.45 s. Under *reduce motion* (the web media query, or Apple's `accessibilityReduceMotion`) everything appears without animation.

### Web layout

The implementation is [styles.css](apps/web/src/ui/styles.css):

- **Width and columns:** maximum width 1504 px. Above 720 px, the card list and inspector sit side by side, split 42/58; below 720 px they stack.
- **Panels and controls:** panels are white with a 16 px radius. Controls are pills at least 44 px tall. The primary action is a stage-coloured fill.
- **Focus:** a 3 px outline in `#2F3BD9` on paper, `#8A90FF` on the stage.
- **Inspector hero:** a 56 px pattern band, then the era label, the year at 112 px (84 px on phones), the title and the artist.

## Component responsibilities

| Component | Responsibility |
| --- | --- |
| App/workspace shell | Deck lifetime, import/export, current card, global error feedback |
| Card list | Ordered selection with stable identity and concise metadata |
| Card inspector/detail | Draft year/source edits, explicit save, selected recording context |
| QR preview | Explicit route choice, exact payload, readable empty state and unverified-mapping label |
| Play home and setup | Provider connection and tier, calibration, mode availability, players, options, card source |
| Host screen | One session: drawing or scanning, clip playback, inputs, reveal, scoreboard, results |
| Playback and scanner services | Provider adapters, clip timing, calibration, camera decoding; no game rules |
| Core/contract layer | Data validity, route selection, scan resolution and every game rule, independent of visual layout |

Keep text and controls rendered by the platform. Generated concept images are design references, not the shipped UI. Fictional sample records must stay clearly identified. Avoid inactive buttons suggesting unsupported playlist fetch or printing; when a game feature can't run (no camera, no exact clips), say why in words.

## Accessibility and QR output

Every input needs a label; selected state must be discernible beyond color; keyboard focus must remain visible. Web errors use alert/status semantics. Long titles and URLs should wrap without horizontal overflow. Use native accessibility and text scaling on Apple; real-device VoiceOver and Dynamic Type testing remain to be completed.

QR output is black on white, with a four-module quiet zone. Preserve the complete payload, avoid overlays or decorative modules, and use a sharp representation. The web renders SVG; Apple uses Core Image. Physical scan reliability and printed dimensions still require real card tests when print output is added.

## Planned playlist and print flow

Follow the [playlist design](docs/playlist-import.md): Spotify or Apple Music input, review candidates, resolve recording/year issues, then create curated cards. Import progress and partial failures belong to this future flow. Preserve user corrections on re-import.

The print surface should add card size, page size, margins, duplex edge, trim marks, and a one-sheet alignment preview before a full export. It should share one ordered manifest for both sides. These are planned controls, not implemented settings.
