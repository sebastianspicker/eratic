# Project status

Updated 2026-10-12. Eratic is a native Mac/iPad/iPhone app and an independent static web companion. This file tracks current capabilities, verification, next steps and open decisions. Historical ledgers and research are archived locally; the [contract](../contract/README.md), [architecture](../ARCHITECTURE.md), [design](../DESIGN.md) and [ADRs](adr/README.md) remain authoritative.

## Implemented

Public positioning focuses on user-curated decks and their linked QR codes. Original HITSTER-card support and official-app compatibility are not advertised features or public roadmap commitments. Existing supplied-URL fields remain technical capabilities, with no automatic catalogue lookup. See [ADR 0013](adr/0013-public-card-support-positioning.md).

- **Decks:** strict import/export of deck versions 1 and 2, stable card IDs, source-backed year curation, optional clip starts, difficulty and related recordings. Both cores run the same contract cases.
- **QR routes:** explicit direct-provider links or supplied official mappings labelled unverified. A provider-independent Eratic route is implemented but unavailable until a card domain is configured. No official-app arbitrary-song compatibility has been demonstrated.
- **Games:** all [nine modes](game-modes.md), with their supported Name It, Stakes, Kids and Sudden Death modifiers, plus Higher or Lower for everyone (lives) and closer-year draws, and a Snippet Ladder buzzer ([ADR 0017](adr/0017-everyone-calls-closer-draws-buzzer-and-relation-suggestions.md)). Session action logs and deck snapshots support saved games and replay; scores come from the cores. Play UX (both apps, 2026-10-11): undo of the last entry before a reveal, slot select-then-confirm on timelines, private Ladder year entry, all-at-once entry for Bullseye and Era Sort, tap-in-order Lineup, preview snippets for Lineup and Original or Imposter, one-tap *Next card*, "Still to answer", staggered reveal with a leader line, card-by-card recap, per-deck personal bests, remembered roster, and linked-recording suggestions in the deck editor. See DESIGN.md.
- **Scanning:** AVFoundation/Vision on Apple; BarcodeDetector or jsQR on the web. Scanning selects cards in the loaded deck and does not open arbitrary URLs. With no print output yet, Setup tells hosts to scan a card's direct-link QR from the Deck tab.
- **Playback adapters:** Spotify, Apple Music and manual playback are selectable without credentials or developer configuration. Native links prefer installed music apps; ordinary provider selection reuses existing Eratic authorization or falls back to QR/song links. Native MusicKit uses the device's subscription after system permission. Interactive authorization for timed playback is optional and requires developer setup for Spotify/web MusicKit. Unknown accounts are not labelled Spotify Free. Without exact clips, Lineup uses titles, Snippet Ladder uses timed preview snippets when available, and Original or Imposter is played by hand from the song backup. Single-card stages also offer on-demand Spotify and Apple Music previews without app credentials. Both have hidden playback with host transport controls; Apple uses the public preview file and offers a revealed embed if that fails or is unavailable. Failed attempts stop and retain retry/fallback controls; late callbacks cannot restart them. Native Apple startup and buffering have bounded waits. QR/app links remain available. Previews do not qualify as exact clips. Live subscription/device behavior remains unverified. See [ADR 0014](adr/0014-app-first-playback.md).
- **Song backup:** every mode shows each card's QR and hidden preview (Spotify/Apple Music) whatever the provider or tier, collapsed behind a disclosure when clips are exact. All nine modes start without exact clips: Snippet Ladder plays each step as a self-stopping snippet of the hidden preview (by hand only when no preview exists), and Original or Imposter is played by hand. A game started without *Use playback* runs as Play it yourself. A silent Spotify autoplay is retried once, then falls back to *Play*. Snippet startup blocks repeated presses; hosts can stop a snippet, and opening the answer stops playback before scoring. Preview failures retain a specific explanation alongside manual fallback: on the web the message names the cause (offline, Apple rate limit, an unanswered lookup or a player blocked by a content filter, or no start in time), and the Apple app reports a build without the MusicKit service as not set up rather than as a connection problem.
- **Sessions:** a reload on the web brings back finished results the host had not left ("Results waiting"), as relaunch does on Apple. New games are written as session version 2, whose Snippet Ladder steps are at most 30 s (default 1·5·10·20·30 s); version 1 games and files stay readable under their old rules ([ADR 0016](adr/0016-session-v2-ladder-step-cap.md)).
- **Storage:** web decks and games persist locally with unreadable-value quarantine; native games persist in Application Support and deck edits require export. No backend or cross-device synchronization.
- **Bug reports:** both apps show their build and offer *Copy diagnostics* (build, browser/system version, recent problems shown to the user); nothing is sent. The web build is `package.json` version plus commit; Apple uses `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION`. Apple also writes those problems to the system log under the bundle identifier (`script/build_and_run.sh --telemetry`).
- **Presentation:** nine era styles, sourced from `design/eras.json`, with scoring boundaries in `contract/eras.json`. QR codes remain black on white.
- **Playlist candidates:** both cores parse playlist references, normalize provider pages, report review issues and promote candidates only with a curated year and source. Shared fixtures cover these rules. No live retrieval or review screens yet.

## Next work

1. Continue focused rendered acceptance for Lineup/Imposter snippet playback, broader native modes and recording suggestions, and iPad/iPhone UI. The actual core suite, both Apple builds, 12 desktop/phone Chrome scenarios and native Bullseye acceptance now pass (2026-10-12).
2. Build playlist review screens in both apps, initially using local fixture pages. Show review issues and proposed years; require a curated year and source before promotion. Re-import must preserve existing cards and IDs.
3. Decide whether candidate lists are transient or persisted. Persistence requires a storage key/quarantine and a strict Swift candidate decoder; synthesized `Candidate` decoding currently does not enforce every schema constraint.
4. Validate live provider access, authorization and intended-use terms before implementing fetchers. The Spotify playlist-items documentation currently restricts access to owned/collaborated playlists; confirm account behavior before promising arbitrary public-playlist import. See [playlist design](playlist-import.md).
5. Add a print-layout model with duplex ordering, margins, trim marks, an alignment sheet and an answer key, then native PDF and browser print output.

## Open decisions

| Decision | Current state |
| --- | --- |
| Eratic card domain | Route implemented; no domain configured. The Pages demo URL is not an official-card mapping or a card resolver. |
| Multi-device play | Out of scope; one host device per game |
| Provider registration and suitability | Adapters implemented; live accounts, credentials and production-use suitability remain unverified |
| Web Apple Music authorization | Optional build-time developer token, minted offline; no signing key in browser assets. A future token service is undecided. |
| Native deck autosave | Explicit export today, with an unsaved-edits marker and confirmations before import and Mac quit; iOS cannot ask before the system ends the app. Document-based autosave is undecided |
| Accessibility variant | The original Snippet Ladder proposal included an untimed variant. Its intended behavior and acceptance still need definition; it is not claimed as a separate implemented mode. |
| Print defaults | Card/page sizes, duplex convention and calibration need an implemented test sheet |
| Licence and release identity | Own code under the MIT License ([ADR 0015](adr/0015-mit-licence.md)). The Apple targets carry version 0.1.0 (build 1), the export-compliance key and all four iPad orientations. Trademark, production bundle IDs, signing team, app icon and native distribution remain unresolved. |

## Public demo

[Source repository](https://github.com/sebastianspicker/eratic) and [GitHub Pages demo](https://sebastianspicker.github.io/eratic/) are public. The Pages workflow deployed successfully, and the live site passed the same twelve desktop/phone smoke scenarios for Timeline, Era Sort, Higher or Lower, Relay, Lineup by name and Daily Eratic. The first hosted Apple CI run exposed a compiler-sensitive array concatenation; explicit appends preserve the standings order and pass all 94 local Swift tests. See [Checks](https://github.com/sebastianspicker/eratic/actions/workflows/check.yml) for hosted verification. The demo uses fictional sample data and has no provider credentials. Account-free editing and manual game hosting remain usable. Do not upload local research, private decks, exports or credentials; publication boundaries are recorded in [ADR 0012](adr/0012-public-repository-and-private-archive.md).
