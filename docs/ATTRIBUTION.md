# Project attribution and design decisions

This project is newly written Swift and TypeScript code informed by the references below. No source code, music catalogue, artwork, or branding from the projects below has been copied into the applications. These are design references, not runtime dependencies. Upstream license descriptions reflect the research snapshot; check the exact revision and preserve required notices before any future code reuse.

## Implementation references

HITSTER Android 4.0.3 informed the separation between authorized Spotify playback and a free fallback. Eratic independently implements a QR/app-link fallback and optional timed-playback authorization; it does not incorporate HITSTER's code, assets, provider identifiers or catalogues. Its separate embed fallback and WebView lifecycle informed the independent preview design; no HITSTER implementation was copied. Eratic uses explicit playback requests, bounded Spotify startup waits and view teardown. It avoids relying on Apple player shadow-DOM internals or repeated autoplay attempts observed in the static Android comparison. Spotify App Remote remains unimplemented. See [ADR 0014](adr/0014-app-first-playback.md) for the platform differences and limits.

Embedded previews use the [Spotify public iframe API](https://developer.spotify.com/documentation/embeds/references/iframe-api) [Apple standard embeddable player](https://artists.apple.com/support/1117-apple-music-marketing-tools) and, for hidden Apple Music previews, the preview file listed by Apple's public [iTunes Search/Lookup API](https://performance-partners.apple.com/search-api). `embeddedPreview.ts` and native `EmbeddedPreview.swift` are independently written integrations; provider media and scripts are fetched only after a preview request, never bundled. Preview duration and availability are provider-controlled, and the preview UI is separate from exact-clip timing.

The web validator generation follows [AJV's standalone validation guidance](https://ajv.js.org/standalone.html): compile schemas during the build so the browser needs no dynamic code evaluation. `apps/web/scripts/generate-validators.mjs` uses the declared AJV dependency to generate validators and bundle its runtime helpers; no example implementation was copied.

The shared contract is in [contract](../contract/deck-v1.schema.json). Swift models, curation, URL policy and QR routes live in `apps/apple/EraticCore`; the web equivalents live in `apps/web/src/core`. The applications should reference this map when a feature adopts one of these ideas. Keep new copied-code attribution separate from conceptual inspiration and record the source revision and license if that changes.

QR image generation uses platform Core Image on Apple and the web application's declared QR dependency. The web app bundles the Bricolage Grotesque variable typeface (SIL Open Font License 1.1) through the `@fontsource-variable/bricolage-grotesque` package, so no font is fetched at runtime. The licence text ships with the site as `apps/web/public/licenses/bricolage-grotesque-OFL.txt`. Apple uses the system font. The web scanner decodes QR codes with the browser's `BarcodeDetector` where available and otherwise with `jsqr` 1.4.0 (Apache-2.0), loaded only when the scanner opens. Apple uses AVFoundation and Vision. Playback uses the providers' own SDKs and APIs (Spotify Web Playback SDK and Web API, MusicKit and MusicKit JS), loaded only when the user connects a provider or explicitly requests an embedded preview. Those are actual implementation dependencies, distinct from the projects above. Dependency manifests and lockfiles identify the installed packages.
